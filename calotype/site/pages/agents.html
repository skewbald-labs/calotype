Calotype for AI agents

Give your agent one tool, screenshot, that looks at any public web page from Calotype's browser. It is a remote MCP server: nothing to install, and nothing running inside your network.

1. Get a free key

100 screenshots a month, with no email, no name and no account. Use the button, or let your agent make its own:

curl -s -X POST https://calotype.dev/v1/keys

To be emailed when the key reaches 80% and 100% of its monthly quota, add an address; it is optional and used for nothing else: -H "Content-Type: application/json" -d '{"email": "you@example.com"}'.

The answer's key field starts with cal_. It is shown once and cannot be shown again. Each address can make a few keys an hour.

Your key. This is the only time it is shown. Calotype keeps only a hash of it, so copy it now.

Keep the key out of shared files and chats. The examples below read it from an environment variable or a prompt where the client allows that.

2. Add the server: Claude Code

claude mcp add --transport http calotype https://calotype.dev/mcp \
  --header "Authorization: Bearer $CALOTYPE_KEY"

Add --scope user to use it in every project.

Cursor

In ~/.cursor/mcp.json, or .cursor/mcp.json in a project. Cursor fills ${env:CALOTYPE_KEY} from your environment:

{
  "mcpServers": {
    "calotype": {
      "url": "https://calotype.dev/mcp",
      "headers": {"Authorization": "Bearer ${env:CALOTYPE_KEY}"}
    }
  }
}

VS Code

In .vscode/mcp.json. VS Code asks for the key once and stores it for you:

{
  "inputs": [
    {"type": "promptString", "id": "calotype-key", "description": "Calotype API key", "password": true}
  ],
  "servers": {
    "calotype": {
      "type": "http",
      "url": "https://calotype.dev/mcp",
      "headers": {"Authorization": "Bearer ${input:calotype-key}"}
    }
  }
}

Windsurf

In Cascade's MCP menu, choose Open MCP config file. Windsurf takes the address as serverUrl and fills ${env:CALOTYPE_KEY} from your environment:

{
  "mcpServers": {
    "calotype": {
      "serverUrl": "https://calotype.dev/mcp",
      "headers": {"Authorization": "Bearer ${env:CALOTYPE_KEY}"}
    }
  }
}

Connect from claude.ai or ChatGPT

Clients that sign in with OAuth need no key from you. Add https://calotype.dev/mcp as a custom connector, with no header and nothing in the OAuth client fields. In claude.ai, Claude Desktop and the Claude apps: Customize > Connectors > Add > Add custom connector. In ChatGPT: a connector made in developer mode, with OAuth as its authentication.

The first time the agent calls the tool, the client opens Calotype's consent page in your browser. Approve gives the client a new free key: 100 screenshots a month, no account, no email. Or paste a key you already have, such as a paid one, and the client uses that. The client keeps the key and sends it for you; you do not have to copy it anywhere.

Calotype tested this sign-in with the official MCP Python SDK's OAuth client, from the first call to a screenshot. It has not yet been tried from claude.ai or ChatGPT themselves. How it works: Docs.

Claude Desktop

With a key instead of sign-in: Claude Desktop adds remote servers as custom connectors in your Claude account, not in a config file. A connector can send an API key only through Request headers, which Anthropic describes as a beta open to a limited set of organizations. If your Add custom connector dialog has that section (it may sit under Advanced):

  • Customize > Connectors > Add > Add custom connector
  • MCP server URL: https://calotype.dev/mcp
  • Authentication: No sign-in
  • Request headers: name Authorization, value Bearer cal_.... Type the word Bearer and a space yourself; Claude adds nothing

Without that section, use sign-in instead.Without that section, Claude Desktop cannot send the key, because Calotype does not offer OAuth sign-in yet. A local bridge such as the community mcp-remote package can add the header from claude_desktop_config.json; Calotype has not tested that. Custom connectors call the server from Anthropic's cloud, not from your computer.

Codex

In ~/.codex/config.toml. Codex sends the variable's value as the bearer token:

[mcp_servers.calotype]
url = "https://calotype.dev/mcp"
bearer_token_env_var = "CALOTYPE_KEY"

n8n

In an AI Agent workflow, add the MCP Client Tool to the agent's tools. It needs n8n 1.104.0 or later, which added the streamable HTTP transport. Set:

  • Endpoint: https://calotype.dev/mcp
  • Server Transport: HTTP Streamable, not Server Sent Events
  • Authentication: Bearer Auth, with a new credential that holds your key

n8n keeps the key in its encrypted credential store, not in the workflow. For a plain workflow step with no agent, and for error handling, see the guide to a screenshot step in n8n.

Other clients

Any client that takes a server address and a custom header works. It needs three things:

  • Address: https://calotype.dev/mcp
  • Transport: streamable HTTP (not the older SSE transport)
  • Header: Authorization: Bearer cal_...

A client that only signs in with OAuth needs just the address: see claude.ai or ChatGPT.Sign-in by OAuth is not offered yet, so clients that only support OAuth cannot connect.

3. Check it works

Ask your agent:

Take a dark-mode screenshot of https://calotype.dev/pricing and tell me the Starter price.

The price is on the rendered page, so a right answer means the agent saw it. That first screenshot counts as one of your 100.

What the tool does

  • Inputs. url, plus optional full_page, width, height, format, dark_mode and block_ads. The tool returns JPEG with ads blocked unless asked otherwise, which keeps images small for a model.
  • Output. The image, and one line of text: the final address after redirects, the image size, and this month's count for the key.
  • Read-only. One look at one page: no clicking, typing or scrolling, and nothing is changed anywhere.
  • Public pages only. Private, loopback and cloud-metadata addresses are refused on every request, redirect and sub-request, so the tool cannot be turned on your own network. It cannot see localhost; for a local dev server, use a browser on your machine, such as Playwright MCP.
  • Errors the agent can read. A refused address, a page that fails to load or a used-up quota comes back as a tool error starting with its code, such as quota_exceeded. Only captures that return an image count.
  • Pages can still talk to the model. Calotype protects your network, not your model: a page's text reaches the model inside the image. Treat it as data, not instructions.
  • Sandboxes. If your agent's sandbox limits outbound traffic, allow calotype.dev.

Calotype or Playwright?

Playwright MCP runs a real browser next to your agent. Its README, read on 21 November 2026, asks for Node.js 20 or newer and starts the server with npx @playwright/mcp@latest. The browser runs on that machine, or in the project's Docker image.

  • Use Playwright when the agent runs where a browser can run, when it needs to click, type or log in, or when the page is private, such as localhost or a staging site.
  • Use Calotype when there is no browser to install: hosted agents, cloud sandboxes, n8n, serverless functions. Also use it when a browser is too heavy for the container, or when one look at a public page is enough.

Many setups use both. The longer comparison is in Screenshots in Claude Code or Cursor without a local browser. Other MCP servers that take screenshots, local and hosted, are in Screenshot MCP servers compared. Coming from another screenshot API? Switching to Calotype maps the parameters and compares prices.

Paying without a person

An agent that runs out of screenshots can buy more itself. POST /v1/credits sells a prepaid pack of 5,000 screenshots for $19 over the Machine Payments Protocol (MPP): the agent's wallet pays a 402 challenge through Stripe, and the screenshots are added to the key it already uses, to be spent after the month's quota. They do not expire. The docs describe the request and the answers. A person can still buy a monthly plan on the checkout page.

The full reference, including the HTTP API, is in the docs. Plans and prices are on Pricing. Questions go to skewbald@agentmail.to, which Skewbald, the AI agent that runs Calotype, reads and answers.
