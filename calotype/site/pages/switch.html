Switching to Calotype

Calotype does one job: a public page address goes in, an image of the page comes back, by HTTP or as one MCP tool call. This page maps other screenshot APIs' parameters to Calotype's and compares prices. It also says where other services do more.

Is it a fit?

Calotype fits when:

  • the pages are public, and one image of each is enough;
  • an AI agent needs to see pages, and it has no browser of its own;
  • the agent should be able to get started alone: a free key comes from one POST /v1/keys, with no account, email or card;
  • the MCP client takes a header but not OAuth. Calotype's remote MCP server takes a bearer key.

Calotype does not fit when you need PDF, HTML input, video, Markdown, cookies or headers for logged-in pages, proxies, element capture, or pages on a private network. Stay with a service that has them. The list is below.

One request, converted

A ScreenshotOne request:

https://api.screenshotone.com/take?access_key=$KEY&url=https://example.com
  &viewport_width=1280&viewport_height=800&format=webp&delay=2&block_ads=true

The same request to Calotype:

curl -H "Authorization: Bearer $CALOTYPE_KEY" \
  "https://calotype.dev/v1/screenshot?url=https://example.com&width=1280&height=800&format=webp&delay_ms=2000&block_ads=true" \
  -o example.webp

The answer is the image itself, with its type in Content-Type. Errors come back as JSON with a code, listed in the docs.

Differences that bite

  • Delay units. ScreenshotOne and ApiFlash take delay in seconds. Calotype's delay_ms is in milliseconds, at most 10,000.
  • Waiting for the network. Calotype's wait_until takes load (the default), domcontentloaded, networkidle or commit. ScreenshotOne's networkidle0 and networkidle2, and ApiFlash's network_idle, become networkidle. ApiFlash waits for the network by default and Calotype does not, so a page that loads data late may need wait_until=networkidle.
  • Sizes. Calotype's viewport defaults to 1280 by 800. It allows widths up to 3,840 and a scale factor up to 3. ApiFlash defaults to 1920 by 1080, and ScreenshotOne allows a scale factor up to 5.
  • Defaults. Calotype's API returns PNG and does not block ads unless asked. Its MCP tool returns JPEG with ads blocked. Allscreenshots defaults to WebP with ads blocked, and ApiFlash to JPEG.
  • The quota is a hard stop. At its limit, a key gets 429 quota_exceeded until the monthly reset, and nothing more is charged. Some services sell extra screenshots above the plan instead.
  • Only successful captures count. A failed capture or a refused request is not counted. See what counts.

Where others do more

These are things other services offer and Calotype does not, as their own pages showed on 19 November 2026:

  • Other outputs: PDF (ScreenshotOne, Urlbox, ScreenshotAPI.net, Allscreenshots), HTML to image (ScreenshotOne, ScreenshotAPI.net), Markdown (ScreenshotOne, Urlbox) and video (ScreenshotOne, Urlbox, ScreenshotAPI.net).
  • Pages behind a login: sending cookies or headers with the request (ScreenshotAPI.net, Allscreenshots).
  • Cleaner shots: hiding cookie banners (ScreenshotOne, Urlbox, ApiFlash, ScreenshotAPI.net), CSS and JavaScript injection, and element capture.
  • Network options: proxies and a choice of IP location.
  • Delivery: upload to S3, caching, webhooks, and no-code integrations such as Zapier and Make.
  • MCP sign-in by OAuth: ScreenshotOne, Urlbox and Allscreenshots run remote MCP servers that sign in with OAuth. Calotype takes a key in a header only.
  • Track record: Urlbox says it has operated for over a decade. Calotype started in November 2026.

Calotype or Playwright?

Many agents get a browser through Playwright MCP. Its README, read on 19 November 2026, asks for Node.js 20 or newer. The server is started with npx @playwright/mcp@latest, and its browser runs on the same machine, or in the project's Docker image.

  • Use Playwright when the agent runs on a machine that can run a browser, when it needs to click, type or log in, or when the page is private: localhost, a staging site, anything behind a login. Calotype cannot reach those.
  • Use Calotype when there is no browser to install: hosted agents, cloud sandboxes, n8n, serverless functions. Also use it when a browser is too heavy for the container, or when one look at a public page is all the agent needs.

The two work side by side: Playwright for your own app, Calotype for public pages. Setup for each client is on For agents. If you write Playwright yourself, Playwright screenshots in Python, and where they break has tested fixes for the usual failures.
